# 第二章 带着一个项目，读懂九段与十步

::: info 样章 · 阅读基线 v0.1
本章中的“示例培训机构”及服务项目均为教学演练。需求、资料条目与工作安排是为说明方法设定的条件，不是客户案例，不代表已经成交或取得经营效果。你可以沿用结构，用自己的真实材料替换。
:::

先把桌面上的东西摆出来。

假设你接到一家小型培训机构的求助。机构有几门课程，也有老师和过去积累的资料。负责人准备更新课程介绍，承担咨询的同事却发现，自己手里的文件无法直接使用：一份介绍面向企业管理者，另一份面向初次接触AI的人；有的材料写了课时，有的只写主题；面对“我们适合哪门课”“能不能按我们部门的任务调整”这样的询问，同事需要来回找人确认。

你学过AI，第一反应可能是把资料全部上传，让它生成一套漂亮的宣传文案。这个动作很容易开始。可文案生成之后，事情未必向前走了一步。哪个版本有效，谁能确认课程范围，客户真正需要先知道什么，这些问题还留在原地。AI可能把资料里的不同说法整理得十分流畅，也可能让原有的冲突变得更难察觉。

本书就从这样的任务开始。你有专业积累，身边也有可以帮助的人。现在需要把一个含糊的请求，变成一项你能说明、能交付、能检验的服务。

## 一、把“帮我们用AI”改成一个有边界的任务

我们给这个演练项目起一个普通的名字：**课程咨询资料整理服务**。

名称不急着追求新奇，先让客户知道你做什么。你要帮助机构把现有资料整理为咨询人员能使用的课程介绍和常见问题回答；如果基础资料已经核准，再逐步做出内部咨询助手，以及需求收集或报价预览原型。

这里的先后关系很重要。资料尚未确认时，不宜直接让助手对外答复。否则它回答得越积极，机构可能越难发现哪些承诺根本没有核准。我们先把资料整理好，再讨论怎样复用，最后讨论哪些环节值得自动化。

把客户的原始请求，和你整理后的任务放在一起看：

| 最初的请求 | 整理后的任务 |
|---|---|
| 帮我们做一下AI升级 | 先整理一门课程的介绍与咨询FAQ，解决同事反复寻找答案的问题 |
| 我们所有材料都给你，你看着办 | 先登记材料来源、版本和确认人；本轮只使用确认可用的资料 |
| 最好做个能自动招生的助手 | 先做内部试用助手，回答范围受已核准资料限制，不能替机构承诺招生结果 |
| 下周能不能给个东西 | 先约定交付物、反馈方式与验收人，再确认日程 |

这张表已经完成了一次指挥动作：你把注意力从某个工具能做什么，转向了当前任务需要什么。

有些人担心，限定范围会显得能力不够。实际交付中，范围说清楚，双方才知道应该把精力放在哪里。你答应“全面升级”，客户可能以为包括获客、成交、教学系统和售后；你做出的却只是一页文案。双方都很忙，最后仍然会失望。

## 二、先找齐三类材料，空白也要留下来

开始之前，请建一张材料登记表。这里不需要复杂系统，一个能持续更新的表格就够用。

| 编号 | 材料 | 本次演练中的状态 | 你要做的处理 |
|---|---|---|---|
| M01 | 当前课程介绍 | 已确认可用；以带版本号的文件为准 | 提取对象、目标、内容、课时和适用条件 |
| M02 | 讲师简介 | 只确认公开简介可用 | 不自行增加头衔、客户名单或资历 |
| M03 | 历史咨询问题 | 示例问题；无真实个人数据 | 整理问题类别，不推断付费意愿 |
| M04 | 价格与定制规则 | 尚未提供或确认 | 标注待确认，由负责人补充 |
| M05 | 过去课程成效 | 本轮没有获准使用的证据 | 不写进宣传文案与助手回答 |

你会发现，表里最有价值的地方，未必是已经填满的格子。M04和M05的空白，告诉你哪些工作现在做不了，哪些话现在不能替客户说。

第一类材料是事实资料：课程到底讲什么，面向谁，现有条件是什么。第二类是业务经验：客户常问什么，同事通常怎样判断，什么问题必须交给负责人。第三类是确认规则：谁能批准材料，什么内容可以公开，发生冲突时以哪个版本为准。

如果只有第一类，AI可以帮你摘要；有了第二类，助手才能更贴近实际咨询；第三类决定这套东西是否值得放心使用。许多看起来像模型能力的问题，向前追一步，会发现是资料和责任没有安排好。

现在请暂停阅读。拿你自己的项目找三份材料，登记文件名、来源、可用范围、日期和确认人。没有的内容写“未提供”，不要让AI替你补齐。

## 三、九段是能力地图，十步是项目要回答的问题

围绕这个小项目，你会逐渐遇到不同层次的工作。

你需要写清任务，让AI知道整理什么，这是提示词；你需要把资料整理、文案制作和检查连接起来，这是工具链；你希望下次遇到同类问题能够复用资料，就会用到知识库。接着，你可能把稳定的问答流程做成助手，用AI编程做需求收集原型，再把任务、客户、版本和交付状态接成一个小系统。

项目继续开展，你还要决定哪些工作自己负责、哪些交给AI或合作方，怎样把方法教给别人，怎样在有限预算下选择更值得做的事。九段因此从个人使用走向业务组织，再走向指挥与判断。

但你不需要一次把它们全部做完。先整理一份介绍和FAQ，也可能已经解决客户最急迫的问题。能力地图帮助你找到缺口，不要求你为了证明段位而堆工具。

十步则从另一个方向追问同一个项目：你凭什么能做这件事？谁需要它？你提出了什么改善？先服务哪一类客户？客户为什么选择你？怎样报价和销售？人和AI怎样分工？钱和时间怎样计算？资源先投在哪里？是否需要外部资金？

两条线在项目中交汇。比如，你可以很快用AI生成一个咨询助手，却仍需要回到用户定位，确认机构同事愿不愿意在工作中使用它。你也可以写出漂亮的销售策略，却需要回到知识库和资料核准，保证实际交付不只是一段演示。

| 当前卡住的地方 | 先回到哪一条线 | 这一轮要留下什么 |
|---|---|---|
| AI总在编造课程细节 | 九段：任务、资料与知识库 | 有出处的回答，或明确的待确认项 |
| 助手能回答，却没有人愿意试 | 十步：用户与创新点 | 对方为什么不用、现有办法有什么便利 |
| 客户觉得服务太大、预算不够 | 十步：销售与资源分配 | 缩小后的服务范围和报价依据 |
| 每次交付都要重新做一遍 | 九段：工作流、系统与岗位 | 可以复用的模板、交接和验收记录 |

这不是一张必须遵守的唯一顺序表。你每走一步，都可能发现前一步的假设需要修改。十步里的融资也允许得出“不需要”的判断。一个靠经营回款维持的小服务项目，不必先把自己讲成等待投资的大企业。

## 四、把第一个版本缩到你能检查的程度

回到示例培训机构。现在有四个候选交付物：课程介绍、FAQ、内部咨询助手、需求收集或报价预览原型。它们可以构成一个完整服务包，但未必适合一起作为第一单卖出去。

我们先作一个判断：**第一轮以课程介绍和FAQ为基础交付，助手与原型作为资料核准后的后续选项。**

理由有三个。基础资料整理是后续工作的共同前提；机构能直接检查内容是否准确；你可以在较小范围里认识双方的配合方式，避免在需求不清时同时承诺多种功能。这是本书的演练选择，你在自己的项目里应写出自己的理由。

请看一个容易出现问题的AI任务输入：

> 帮我给一家培训机构写AI升级方案，突出我们的优势，最好让客户觉得非常值得购买。

这种任务把AI推向了说服，却没有给它核查依据。下面是一份为教学编写的**可能出现的失败输出示意**，不是实际模型运行记录：

> 我们将打造全天候自动招生系统，全面提升转化效率，覆盖课程推广、智能咨询和个性化成交，让机构快速实现增长。

问题不在于句子是否好听。你无法根据现有材料验证“全面提升”，也没有约定“自动招生系统”包含哪些功能。客户即使认可了这段话，你也还没有一份能开展工作的任务单。

我们把输入改成这样：

```text
请协助起草“课程咨询资料整理服务”的项目起点卡。
这是教学演练，不写成已成交案例。

已有输入：M01已核准课程介绍、M02可公开讲师简介、
M03示例咨询问题。价格和定制规则未确认，不能补写。

本轮只交一门课程的介绍和咨询FAQ。
内部咨询助手、需求收集或报价预览原型列为后续选项。

请输出：服务对象、当前问题、本轮交付、不包含的内容、
客户需提供的材料、待确认问题、验收方式。
每项必须能追溯到以上条件；不能推断成效或填造数据。
先指出条件里还缺什么，再给起点卡草案。
```

注意最后一句。它给了AI一个表达不确定性的出口，避免所有空白都被包装成自信的句子。但这也不意味着你可以免除检查。你仍需对照材料，把AI写多了的承诺删掉，把说不清的地方送回客户确认。

## 五、一页项目起点卡：填完才能开始做

下面是填写后的演练版本。它只给你看怎样把任务落到纸面，不代替真实项目的协商。

| 字段 | 填写示例 |
|---|---|
| 项目名称 | 课程咨询资料整理服务 |
| 服务对象 | 示例培训机构的课程负责人和咨询同事 |
| 当前问题 | 资料版本不统一，常见问题需要反复找人确认 |
| 本轮目标 | 让咨询同事能在核准资料中找到课程基本信息；不承诺咨询或成交数量 |
| 本轮交付 | 一门课程介绍、FAQ、来源与待确认清单、版本记录 |
| 后续选项 | 内部咨询助手；需求收集或报价预览原型，另定范围与费用 |
| 客户输入 | 可用资料、内容确认人、反馈时间安排 |
| 人的责任 | 判断资料是否准确，确认公开范围，批准最终文本 |
| AI的任务 | 整理、比对、起草、列出矛盾与缺项；不能决定价格或替机构承诺 |
| 开始条件 | 资料可用范围已确认，有人负责核准内容 |
| 验收办法 | 按已核准资料逐项对照介绍；以常见问题检查FAQ；无法回答的项目列入待确认清单 |
| 暂停条件 | 关键资料互相矛盾且无人确认，或需求超出本轮范围 |
| 商业状态 | 演练项目；价格、成交、交付效果均未发生 |

起点卡里还没有一个漂亮的作品。但你已经知道从哪里开始，遇到什么情况该停下来。很多项目返工，原因是第一天没有把这些关系说清楚。

当客户把需求加到“最好还能自动收集线索”时，你可以把它记入后续选项，说明需要哪些额外材料和功能测试。你也可以判断它比当前任务更重要，重新调整本轮范围。调整可以发生，但必须留下记录，让双方知道替换了什么。

## 六、留下证据，让下一章接得住

读完这一章，你至少应有三样东西：项目起点卡、材料登记表、待确认清单。把它们放进同一个项目目录，给文件写上日期和版本。

再建一个简单的状态栏：哪些是资料已经确认的事实，哪些是你和AI提出的解释，哪些还只是准备验证的假设。后面章节产生的访谈、原型、报价、交付和现金流记录，都沿用这个区分。

你可以把项目资料分成八组：原始资料、任务定义、需求证据、样品版本、报价沟通、交付记录、成本与现金流、复盘。分组的目的，是在任何时候都能回答“这句话从哪里来”“这个方案为什么改”“这个结果真的发生了吗”。目录不用复杂，持续使用比形式整齐更有价值。

如果你是第一次尝试，先完成起点卡，再练任务表达与资料整理。如果你已有业务，可以从一个反复返工或需要重复解释的环节切入。如果你是学生，请找一个真实使用者，在开展工作前讲清楚这是学习项目，别把模拟反馈写成市场验证。

这一章的最后，请把起点卡交给一个不了解你项目的人。请他根据卡片复述：你准备为谁解决什么问题，最后会交出什么，还不能承诺什么。听完不要急着解释，先把他误解的地方记下来，再改卡片。

这次修改很小，却已经是创业工作的一个完整动作：提出方案，让外界看见，听取反馈，重新定义。接下来练九段、走十步，我们会一遍遍重复这个动作，让项目逐渐接近真实的使用与经营。
