# 第17章 第六步·销售策略

> 《创业AI指挥官——AI九段高手十步问道》样章  
> 张建勇 吴鹏

::: info 本章演练说明
本章沿用“示例培训机构”的“课程咨询资料整理服务”。机构、需求、反馈和报价均为教学演练设定；所有金额只是演算假设，不是市场指导价，不代表实际成交或经营结果。示例消息供读者改写，未向任何人发送。
:::

你已经为示例培训机构做出一份课程介绍、若干常见问题答案，还能演示一个内部咨询助手。打开演示页面，输入问题，助手能够根据资料整理答复。到这一步，事情很容易出现一种错觉：作品已经能用了，销售应该只是把链接发出去。

于是，你写下第一版介绍：“我们提供AI赋能的课程咨询解决方案，涵盖知识整理、智能问答与数字化原型，全面提升机构运营效率。”

这句话有不少听起来有价值的词，却没有告诉机构负责人：我现在要拿哪些资料给你，你会替我完成哪件事，几天能交，交来以后谁使用，以及我需要付多少钱。

读者在这一章要完成的，就是把这几件事讲清楚。销售从一份能被理解、能被交付的约定开始。AI可以帮助你整理资料、准备物料和分析反馈；服务范围、价格与对外承诺，需要你自己决定。

## 一、先卖一件能说清楚的事

回到演练项目的起点：示例培训机构手里已有课程文件，工作人员却需要在多个版本中查找内容。同一个问题，不同人可能引用了不同日期的介绍。我们暂时提出一个服务假设：将获准使用的课程资料整理成一套统一口径，供内部工作人员查阅。

请注意，文件分散并不能自动证明客户愿意购买整理服务。负责人也许认为工作人员现阶段能够处理，也许更急着解决招生问题。你需要通过访谈确认这件事是否值得投入。在本章演练中，我们先假设负责人愿意讨论资料整理，尚未认可助手和原型的必要性。

把服务写成下面这一句，客户才容易接着问下去：

> 我们根据你确认过的课程资料，整理一份课程介绍和一份常见问题答复表，标明资料来源与待确认事项，让内部咨询人员可以按统一版本查阅。

这句话没有替客户许诺招生增长，也没有把“智能”当作购买理由。它描述了眼前的问题、具体工作和使用者。若客户关心的是招生转化，你还要继续问，统一资料究竟能支持哪个环节，是否还有别的工作更值得先做。

现在请打开自己的项目起点卡，把“AI赋能”“一站式”“全流程”这类词先移开，用一句话写出你准备承担的结果。如果一句话仍然塞进五六项服务，说明你还需要做取舍。

## 二、把作品拆成可以验收的服务包

贯穿全书的项目最终包括四类成果：课程介绍、FAQ、内部咨询助手，以及需求收集或报价预览原型。它们共同组成能力练习，也可以分阶段成为服务。第一次销售时，没有必要让客户同时购买全部成果。

先做一张范围表，逐项问自己：这件东西交给谁，客户怎样知道它完成了？

| 成果 | 客户提供什么 | 我交什么 | 怎样验收 |
|---|---|---|---|
| 课程介绍 | 已确认的课程与讲师资料 | 一份可编辑介绍稿 | 关键字段与确认资料一致；未知项有标记 |
| FAQ | 常见咨询问题及允许使用的答案依据 | 一份问题、答案、来源对照表 | 逐条可追溯；无依据的问题进入待确认清单 |
| 内部咨询助手 | 已审定介绍与FAQ | 一个供指定人员内部试用的助手 | 按约定问题测试，能识别缺资料并转人工 |
| 轻量原型 | 已确认的字段和使用流程 | 一个需求收集或报价预览原型 | 约定路径可演示，展示与正式功能状态标清 |

看这张表，你会发现制作助手之前，客户必须先确认知识资料。资料没有审定，助手做得再流畅，也可能把旧信息传播得更快。因此，先卖资料整理基础包，有时比先卖全套系统更符合项目顺序。

服务包还需要写清边界。演练基础包限定为一门课程、一份介绍、十五条FAQ、一轮集中修改。课程数量和问题数量只是本章假设，读者应按自己的工作量确定。客户提供资料，指定一名确认人；你负责整理、标记矛盾、提出待确认问题，不替机构认定未经确认的课程事实。

内部咨询助手和轻量原型进入后续阶段，分别报价、分别验收。跨平台接入、自动对外回复和长期维护，也需要另行确认。把这些写出来，客户才知道自己买到哪里，你也才能判断能否按时完成。

在发出报价前，先替客户读一遍交付文件目录。完整演练包可以这样列：课程介绍稿、FAQ及来源表、内部助手使用说明与测试记录、轻量原型演示说明、最终交付清单。单看目录，客户就应知道“我拿到的是什么”。让对方猜测文件内容，会把第一次沟通拖进大量解释。

还要问清客户内部谁需要点头。咨询人员觉得好用，不代表负责人愿意支付；负责人认可方向，也不代表资料确认人能按时提供文件。把使用者、付款决定者和内容确认人分别记下来，沟通时就知道每一次要解决什么。小机构里三种角色可能是同一个人，仍应把三件责任说清。

## 三、让AI帮你拟报价，先把成本交代给它

一种常见做法是直接问AI：“这项服务应该卖多少钱？”它很可能生成一份看似专业的价格表，但如果它不知道你的资料量、返工风险与交付标准，给出的数字很难成为决策依据。

先估算你自己要投入什么。下面仍是演练假设，用于说明算法：

| 基础包工作 | 预计工时 |
|---|---:|
| 接收、检查资料与列问题 | 1小时 |
| 整理课程介绍与FAQ初稿 | 2小时 |
| 人工核对来源与关键字段 | 1.5小时 |
| 集中沟通与一轮修改 | 1小时 |
| 整理交付文件及说明 | 0.5小时 |
| 合计 | 6小时 |

假设你为自己预留每小时100元的劳动成本，六小时为600元；再假设本单分摊工具成本50元，留出100元返工余量，成本预算共750元。若基础包演练报价为1000元，剩余250元还要面对估时偏差和其他未计成本。这个差额不等于已经赚到的净利润。

这里的100元、50元和1000元都不是推荐标准。你要做的是把自己的工时和支出放进去，再判断客户愿意支付的金额能否覆盖服务。还应在实际报价前说明税费、开票、支付和交付条件的具体安排，不让未说明事项藏在总价中。

有了这些输入，再请AI协助：

> 请帮我检查报价方案，不替我决定价格。  
> 服务名：课程咨询资料整理服务。  
> 客户：示例培训机构，本次仅处理一门课程。  
> 基础包：一份可编辑课程介绍、十五条FAQ及来源表，一份待确认问题清单，一轮集中修改。  
> 预计总工时六小时；劳动成本按每小时100元演算；工具分摊50元，返工余量100元。以上均为教学假设。  
> 拟报价1000元。内部咨询助手与轻量原型另阶段评估。  
> 请检查范围遗漏、可能增加工时的情况和验收歧义，输出问题清单，不补造市场行情或客户意愿。

假设AI提醒：“客户迟迟不确认资料，交付日期怎么办？”这是一条值得采纳的检查意见。你可以把“确认齐备资料后开始计时”写进报价说明，并约定等待确认时怎样调整排期。若它建议“承诺节省80%咨询时间以证明价值”，则应删除：本项目没有测量这个结果，也没有证据支持这样的承诺。

## 四、写出一张客户能作决定的报价单

完整项目的首次演练报价设为2800元。客户尚未认可全部成果，所以我们先把完整包与基础包都写清，以便讨论。下面展示范围收缩后的基础包报价示例。

| 项目 | 报价内容（全部为演练假设） |
|---|---|
| 服务 | 课程咨询资料整理服务·基础包 |
| 范围 | 一门课程；一份课程介绍；十五条FAQ及来源表；待确认事项清单 |
| 客户配合 | 提供获准使用的资料，指定一名内容确认人，集中反馈 |
| 交付形式 | 可编辑文件及阅读版；注明版本日期与待确认项 |
| 排期 | 资料确认齐备后四个工作日提交初稿，修改排期另约 |
| 修改 | 含一轮集中修改；新增课程或新增成果重新评估 |
| 价格 | 1000元，税费及开票安排在正式确认前写明 |
| 付款 | 演练设定为启动时500元、验收后500元；实际条件由双方明确约定 |
| 验收 | 对照资料核查关键事实，十五条FAQ逐条有来源或明确待确认 |
| 后续阶段 | 内部咨询助手、轻量原型及持续维护另行评估 |

报价单的作用，是让双方对同一件事情作决定。客户同意的是这份具体范围，你承接的也是这份范围。对方说“顺便再帮我加一个报名系统”，你应先判断它会怎样改变工作量、交付日期和责任，再提出新的安排。

动手时，让AI把范围表改成一页报价单很方便。完成后请逐项倒查：每一句“支持”“包含”“自动”对应什么可演示行为？你亲自做过的，才写成能力；尚在评估的，写成待确认。文件看起来漂亮，不能代替这一步核对。

最初2800元完整包也应有同样的说明，不能只剩一个总价。演练设定为：一门课程的介绍与十五条FAQ、一个仅供内部试用的咨询助手、一个报价预览原型，以及使用说明和一轮集中修改。原型只显示输入条件与报价预览，不接真实收款；助手不自行向外部客户发送答复。预计交付八个工作日，从资料确认齐备后计算。它与1000元基础包的差额，对应的是新增制作、测试和交接工作。

客户看到2800元时，看到的是完整包的这组承诺。后来改为1000元，交付范围也随之改变。两张报价单保留各自的版本号和日期，新的确认文件写明以哪一版为准，避免沟通中混用旧范围与新价格。实际承接前，还要把款项、发票和验收异议的处理方式写全。

## 五、没有成交，先看客户究竟拒绝了什么

现在加入一条模拟反馈，用来练习修改。它不是来自真实客户的对话：

> “我们现在最多考虑1200元。课程信息确实要整理，但员工暂时不想学新工具，助手和页面以后再说。你能不能先把介绍和常见问题做好？”

如果你只记下“客户嫌贵”，下一步很容易变成把2800元降到1200元，仍然承诺原来的全部交付。项目看起来更接近成交，实际却把成本压力留给了自己。

这条反馈至少包含三层信息：预算有上限；资料整理有讨论价值；工具采用存在顾虑。于是，本章示范作出的选择是缩小范围，先做1000元基础包，助手与原型延后。这样既回应了客户当前要解决的问题，也保留了完整项目的分阶段路径。

可以把模拟答复写成这样：

> 理解。我们先处理课程资料，暂不要求员工使用新工具。基础包包含一门课程介绍、十五条常见问题答复和来源对照，另列需要贵方确认的信息，演练报价为1000元。贵方集中确认资料并反馈一轮修改。若后续确实需要内部咨询助手，再根据已经审定的资料评估下一阶段范围。

这个修改是否值得采用，还要由你重新核算。假如客户资料过于混乱，六小时根本做不完，1000元也可能不合适。你可以减少首批问题数、延长排期、提出付费诊断，或者决定暂不承接。客户预算是判断条件之一，不能单独替你决定项目。

不要请AI为这条模拟答复打一个“成交概率90%”的分数。它没有参加真实讨论，也不知道客户内部的优先级。更有用的追问是：“如果客户答应基础包，启动前仍有哪些条件没有确认？”你应该得到的是待办：课程范围、资料清单、内容确认人、验收样例与付款安排，而不是一份虚构的胜率。

若下一次反馈是“我们现有员工能做”，也不必立刻证明自己更强。你可以问对方是否愿意说明目前怎样更新资料、最容易出错的是哪一步。如果现有办法已经足够，记录这个结论，回到用户定位章调整对象。如果确有反复返工，再比较你能承担哪一段。能识别一个暂时不值得跟进的对象，也是销售中的判断。

把第一版与修改版并排存下来，在改动旁边写一句原因。真正可复用的经验，就藏在这些选择中。

## 六、把对外尝试留下来，别把热闹当结果

完成演练后，你可以把自己的服务介绍改成一条简短邀请，发给确实可能需要、且适合联系的人。先说明联系来由、你观察到的问题，以及希望进行的下一步；不要一上来塞进所有链接。

示例表达可以是：“我在整理课程咨询资料的工作方法。如果您目前也遇到课程版本分散、答复口径不一致的问题，我想了解一下具体流程。方便时可先聊十分钟，再判断是否值得做整理。”真实发送前，应按双方关系与真实情况改写，不冒充已经了解对方业务。

一次小范围尝试后，把结果记下来：对方是否回复，谈到了什么，是否愿意提供资料，是否收到报价，接下来由谁在什么时间完成什么动作。点赞说明有人看到，咨询说明有人愿意讨论，付费说明出现一次购买，交付验收才说明这次服务完成。它们各有意义，不能互相代替。

请复制下面的空白表。真实触达由读者自行决定并完成，本书没有替你向任何人发送消息。

| 日期 | 联系对象或匿名编号 | 联系依据 | 对方原始反馈摘要 | 所处阶段 | 我的下一步与日期 | 可追溯记录位置 |
|---|---|---|---|---|---|---|
|  |  |  |  | 未回复／访谈／询价／报价／成交／拒绝 |  |  |

记录中别只写“意向强”。写“愿意在周五前提供一份课程资料供评估”更有用，因为它对应一个可观察动作。保存反馈时只保留项目必要的信息，公开展示前去除联系方式和无关个人资料。

复盘时将记录分成三栏：“对方说了什么”“我如何解释”“我下一次怎样验证”。例如，原话是“本月没有预算”，你的解释可能是预算时间不合适，也可能是价值没有讲清。先把两种解释都留下，再约定合适的后续动作，不能把个人猜测写成客户事实。若对方明确不需要或不愿继续沟通，就结束本轮联系，换一个更合适的对象检验假设。

本章的任务，是完成一份服务说明、一张报价单和一次销售尝试复盘。尚不适合对外联系时，先用演练完成材料，把没有得到真实验证的部分明确留空。你可以没有成交，但应能解释：本轮接触到了谁，听到了什么，哪项假设改变了，下一次准备调整什么。

回到最初那句“AI赋能的课程咨询解决方案”。现在，你可以把它展开为具体成果、明确范围、可复核成本与双方都理解的验收。客户仍然可能拒绝，项目也仍有不确定性；但你已经有了一份可以讨论、可以修订、可以负责的服务。

下一步进入团队组织：当有人愿意购买这项服务，你怎样安排自己、AI和合作方，让报价单上的每一项承诺都有着落。
